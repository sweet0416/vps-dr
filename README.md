# VPS DR 中文安装与管理

在 VPS 的 **root SSH 终端**执行，一条命令打开中文菜单。

```bash
curl -fsSL https://raw.githubusercontent.com/sweet0416/vps-dr/main/bootstrap.sh | bash
```

首次安装选 **1**，导出客户端链接或二维码选 **2**。已有节点输入 `caidan` 打开本机菜单，选 **5** 更新管理脚本，选 **14** 更新 Xray 核心。

## 菜单功能

| 数字 | 操作 | 说明 |
| --- | --- | --- |
| 1 | 安装 / 继续安装 | 新建节点，或补齐中断安装；复用本机已有 UUID |
| 2 | 节点链接与二维码 | 自动识别公网 IPv4，失败时可手工输入 |
| 3 | 检查运行状态 | 核对配置、服务、进程和本机 TCP 443 |
| 4 | 重启节点服务 | 重启前核对 systemd 实际加载的服务文件和覆盖项，重启后检查本机健康 |
| 5 | 检查更新 / 升级管理脚本 | 在线获取 main 最新代码，更新菜单及工具，保留节点和核心 |
| 6 | 一键开启 BBR | 检查当前内核支持，保存原设置并启用 BBR |
| 7 | 流量统计 | 本月及采集以来的整机出口网卡收发流量 |
| 8 | 连接诊断 | 本机配置、443、公网 IP、防火墙提示 |
| 9 | 连接数与资源占用 | TCP 443 连接数、主机内存/负载、Xray 内存与累计 CPU |
| 10 | 备份节点配置 | 创建仅 root 可读的 UUID、配置及状态备份 |
| 11 | 恢复节点配置 | 输入备份绝对路径并确认，失败尝试回滚 |
| 12 | BBR 详情 / 恢复设置 | 查看算法、恢复首次开启前设置，或明确选择 cubic |
| 13 | 查看近期故障日志 | 最近 50 行 Xray 日志，隐藏 UUID 和节点链接 |
| 14 | 检查更新 / 升级 Xray | 查询官方最新稳定版，校验后升级核心，失败回滚 |
| 0 | 退出 | 返回终端，保留上次操作的退出码 |

每次操作后返回菜单，失败会解释原因及退出码。选 5 升级成功后会自动打开新菜单。菜单从 `/dev/tty` 读取选择，通过 curl 管道运行也需要交互终端。

面板顶部刷新服务和 BBR 状态。青色编号、粗体和绿色运行状态仅在支持颜色的终端显示；非空 `NO_COLOR`、简易终端和重定向输出使用纯文本。字体、字号和背景色由 SSH 客户端设置。

## 首次安装与旧节点升级

首次安装默认生成新 UUID，使用当前 VPS 公网 IPv4，域名可选。当前 `main` 上的安装、预检和导出流程通过私有状态文件 `/etc/vps-dr/state.json` 传递节点凭据。首次安装时，核心、配置和服务文件各自在目标目录写完并同步后才发布。若复制中断，再选 **1** 可复用原 UUID 并补齐缺失文件。

已有节点运行上方入口选 **5**。会核验已知管理脚本、当前官方核心摘要、配置和 unit，保留 UUID、核心、节点配置和运行状态。管理脚本升级后会部署每分钟流量采集 timer；采集启用失败会单独提示，可修复后再选 5 重试。管理升级不重启 Xray。

支持从已发布的 `v1.0.0`、`v1.1.0`、`v1.2.0` 和已识别的旧版 main 面板升级，也支持仅手工修改 DOMAIN 赋值的已知修复。遇到未知脚本、程序、unit、覆盖片段或端口占用时，请按预检提示核对。

本机管理版本可在 `/opt/vps-dr/VERSION` 查看。状态文件中的 `deployment_version` 记录最初部署版本，升级后可以继续显示旧版本。

## 管理脚本与 Xray 更新

**已装过 1.2.0 的节点也可以选 5 获取修复。** 固定标签 `v1.2.0` 对应提交 `d97ea68`。后续修复于 2026-11-22 合入 `main`（`12ec173`），覆盖 IPv4 监听识别、凭据传递、安装中断续装和核心升级回滚等问题。两者的 `VERSION` 都是 `1.2.0`。菜单 5 会在线获取 `main` 并比对管理文件内容，版本号相同也能更新。[固定发布](https://github.com/sweet0416/vps-dr/releases/tag/v1.2.0) · [修复记录](https://github.com/sweet0416/vps-dr/pull/6)

需要复现原版 `v1.2.0` 时，入口与下载 ref 都指定同一标签。

```bash
curl -fsSL https://raw.githubusercontent.com/sweet0416/vps-dr/v1.2.0/bootstrap.sh | VPS_DR_REF=v1.2.0 bash
```

在上述固定快照的菜单中选择 **5**，也会转到 `main` 的最新管理代码。

首次安装使用固定的 **Xray v26.3.27**。安装器将下载的 ZIP 与仓库固定的 SHA-256 和官方 `.dgst` 核对，再校验解压后的核心。选 **14** 查询官方最新稳定版，有更高版本时输入 `YES` 才会升级。[Xray 官方稳定版](https://github.com/XTLS/Xray-core/releases/latest)

升级前验证现有受管程序、配置和实际 systemd unit，下载官方架构 ZIP，核对 `.dgst` 与发布 API 提供的 SHA-256（如有），从已验证 ZIP 提取核心并计算二进制摘要，执行版本及现有配置测试。切换前会再次核对服务运行状态，若与升级开始时不同，升级会退出。版本与摘要以 root 私密记录保存在 `/etc/vps-dr/core.json`。升级后续装、状态检查及配置恢复会识别受信新版核心，不重新覆盖成初始固定版本。

核心切换会短暂重启原本运行的服务；原本停止的服务保持停止。配置和 UUID 保持不变，失败尝试回滚原核心、状态和运行状态。中断记录位于 `/etc/vps-dr/core-update`，下次菜单或相关管理操作先恢复。回滚本身失败时保留记录并报错，需处理磁盘、权限或 systemd 问题后重试。**本机检查通过仍需在客户端测试实际连接。**

## 流量与运行诊断

流量采集在安装或管理升级时启用 `vps-dr-traffic.timer`，每分钟读取默认出口网卡计数，持久保存到 `/var/lib/vps-dr/traffic.json`，文件权限 600。

- 本月按 **UTC 自然月**统计；累计值从首次成功采集开始，不追溯安装前流量。
- 统计主路由表中 IPv4/IPv6 默认出口网卡，并按网卡去重；包含 SSH、系统更新等整机流量，不能当作每用户或纯节点用量。
- 网卡切换、计数重置、关机前未采样或复杂策略路由可能导致漏计；跨月间隔的增量归入当前采样月。界面显示采集起点、最新时间及中断提示。
- `连接数` 是本机 TCP 443 已建立连接数，同一客户端可有多个连接，不能视作人数。CPU 显示进程启动后累计使用秒数。

连接诊断读取本机服务、配置、监听进程和回环端口，并提示公网 IP、UFW/nftables 规则。公网查询失败不会把本机健康服务判为故障。云安全组、上游网络、VMess 客户端握手及网站速度仍需外部实际验证。

故障日志只读最近 50 行，去除终端控制字符，并隐藏 UUID、vmess 链接及常见密码/token 字段。分享前仍应检查 IP 等个人信息。

## 私密备份与恢复

菜单 **10** 默认保存到 `/var/lib/vps-dr/backups`，目录 700、文件 600。备份含 UUID、Xray JSON 配置和部署状态，以及格式、时间、架构和 SHA-256 校验。**不含核心程序、systemd unit、BBR 设置或流量历史**。校验和用于检查损坏，不能替代备份来源验证。

请另存一份到自己控制的安全位置，重装 VPS 前尤其如此。备份是节点凭据，不能提交 GitHub 或公开分享。

菜单 **11** 先列出现有备份。输入本机备份的绝对路径，再输入 `RESTORE` 确认。迁移到另一台 VPS 时，先选择 1 完成受管节点安装，再放入同 CPU 架构的私密备份并恢复。导出时自动使用新 VPS 的公网 IP。

恢复会采用备份 UUID 和配置，保留本机已验证的核心及管理版本，恢复前自动保存 `before-restore` 备份。运行中的服务恢复后执行本机健康检查，停止的服务保持停止。失败或中断时用私密 journal 回滚原配置；检测到恢复之外的未知修改会停止并保留现场。恢复成功后，用菜单 2 重新导出客户端链接。

## BBR 状态与恢复

顶部状态来自 `net.ipv4.tcp_congestion_control`。默认算法为 `bbr` 时显示绿色“已开启”；其余显示算法名；读取失败显示“状态不可用”。

选择 **6** 检查当前内核支持，必要时加载当前内核自带 `tcp_bbr` 模块，设置并回读，然后保存到 `/etc/sysctl.d/99-vps-dr-bbr.conf` 与 `/etc/modules-load.d/vps-dr-bbr.conf`。保持本机队列规则和内核版本。

首次开启前保存 `/var/lib/vps-dr/bbr-original.json` 私密原状态，重复开启不会覆盖该记录。选择 **12 → 1** 并确认，可恢复首次开启前的默认算法及本项目原配置。历史旧版开启 BBR 且没有原状态记录时，会说明无法推断原设置；可单独选择 **12 → 2**，输入 `YES` 切换为 cubic。cubic 操作移除本项目 BBR 持久配置，重启后算法由其他系统配置及内核默认值决定。

BBR 与恢复算法只影响后续新建 TCP 连接，实际速度取决于线路和网络条件。遇到不受支持的内核、冲突持久设置或未知文件，会给出稳定错误码及中文解释。变更失败尝试还原，回滚失败会单独报告。

## 地址、二维码与无人值守

菜单 2 自动查询公网 IPv4，失败后可手工输入 IPv4 或显式域名。也可设置 `VPS_DR_SERVER` 或可选 `VPS_DR_DOMAIN`，环境变量须传给管道右侧的 bash。域名应解析到当前 VPS。

已安装节点可用 `bash /opt/vps-dr/export-client.sh --server example.com --qr` 指定域名，省略 `--server` 自动导出 IP。链接、二维码和手动参数使用同一地址与 state/config UUID。二维码工具安装或显示失败仍会输出 vmess 链接。UUID、链接和二维码只应在私密终端查看，不写入公开测试产物或 CI 日志。

自动安装入口，不进入交互菜单。

```bash
curl -fsSL https://raw.githubusercontent.com/sweet0416/vps-dr/main/bootstrap.sh | bash -s -- --install
```

将末尾参数换成 `--preflight` / `--dry-run` 可只预检，`--upgrade-management` 可只部署在线下载的管理脚本。重定向安装输出不会自动打印客户端密钥。

## 安装保护和验证范围

Ubuntu 22.04/24.04/26.04、Debian 12/13，amd64/arm64，需要 systemd、1 GiB 可用磁盘和 256 MiB 可用内存。配置在启动前及 systemd ExecStartPre 校验；管理脚本先于服务启动和健康检查部署。安装、升级、重启、BBR、备份恢复共用非阻塞锁；锁拒绝链接、特殊文件和不安全权限。流量采集另用私有锁，避免和界面读取相互覆盖。

管理升级使用同盘暂存与重命名，原目录保存在 `/opt/.vps-dr.backup-*`。交换中断时下次恢复 `/opt/.vps-dr.previous`；管理备份不含节点密钥。回滚可在共享锁下调用 `manage.py rollback`，使用升级输出的具体同目录备份路径。旧脚本自身不一定支持新版核心元数据，回滚管理版本后如有不兼容，应重新用在线入口升级。

仅在现有 UFW 已激活且缺少规则时放行 TCP 443。服务商安全组仍需自行放行。停用脚本会停用本项目 Xray 和流量采集，保留私密状态、备份和流量历史；BBR 可从菜单单独恢复。
